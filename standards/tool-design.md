# 工具设计规范（Tool Design）

适用范围：`src/` 下的所有工具。本文件是工具设计与评审的权威规范，工具实现应与本文件保持一致。

## 1. 基本定位

- 一个目录代表一个工具，专注解决一组**相关**问题。
- 可以暴露多个相关命令（如检查、清理、删除），但不得把不相关的功能合并进同一个工具。
- 工具应能独立开发、运行、复制和迁移。

## 2. 独立性（Self-contained）

- 工具的源码、内部模块、第三方依赖和必要配置都放在工具自己的目录内。
- 禁止 import 其他工具目录中的源码。
- 不引入仓库根级别的运行时模块、共享运行时层、工具注册中心或跨工具工具包。
- 接受为保持独立而产生的合理代码重复，不为消除少量重复抽取公共模块。
- 工具内部可随复杂度自行拆分模块，但拆分边界不超出工具目录。

## 3. 目录与命名

- 路径统一为 `src/<category>/<tool>/`，分类目录按需创建，不预先建立空分类。
- 分类名和工具名一律使用 `kebab-case`，保持简洁明确。
- 工程结构随实际复杂度渐进，不为假想需求预埋结构：
  - 简单工具：`index.*` + `README.md`（trivial 时 README 可省略，用注释代替）。
  - 标准工具：入口 + 命令/模块目录 + 必要的 `package.json` 等声明文件 + `README.md`。
  - 复杂工具：可在工具内部使用 `src/`、`tests/`、`tsconfig.json` 等。

## 4. 技术选型

1. 默认优先使用 TypeScript + Node.js。
2. 当 Python、Rust、Shell 或 PowerShell 有明确实际优势时可以选用。
3. 不在工具间强制统一语言或执行模型。
4. 选择与工具实际复杂度匹配的最简结构。
5. 标准库足够时优先使用标准库。
6. 第三方依赖保持最少，并在工具目录内声明。
7. 修改已有工具时沿用其现有语言、约定和风格。
8. 没有具体需要时，不引入框架、构建系统或抽象。

## 5. 入口与命令

- 每个工具必须有明确的执行入口和运行方式。
- 简单工具不需要命令分发框架。
- 多命令工具由入口负责命令注册与分发，命令的具体逻辑放在独立模块中。
- 应允许调用系统原生命令和外部程序，但必须在 README 中说明相关环境要求。

## 6. 参数与配置

接受参数的工具应同时支持以下两种参数来源：

1. **文件内默认值（In-file defaults）**：入口文件顶部提供边界清晰的默认配置区，使用语义化常量（如 `DEFAULT_NAME`、`DEFAULT_RECURSIVE`）。用户可直接修改文件后运行，无需记忆命令行参数。
2. **命令行参数（CLI arguments）**：通过位置参数和选项传入，覆盖文件内对应的默认值。

规则：

1. **CLI 优先**：命令行参数始终优先于文件内默认值；任何通过 CLI 显式传入的值都以 CLI 为准。
2. **默认配置区小而扁平**：保持在入口文件顶部，用注释明确标出可编辑范围，让用户一眼知道可以改什么。
3. **禁止提交个人信息或凭据**：默认值不得包含姓名、邮箱、Token、机器相关路径等；使用空字符串或中性占位值。
4. **必填值缺失保护**：必填值在两种来源中均为空时，打印用法说明并以非零状态码退出，不产生任何副作用。
5. **布尔选项同样支持默认值**：如 `--recursive`、`--dry-run` 可在文件内预设（如 `DEFAULT_RECURSIVE`）；传入对应标志即启用该行为。
6. **必须文档化**：工具 README 需说明两种参数来源、优先级关系，以及位置参数的顺序限制。

## 7. 安全

对于删除文件、批量修改、系统变更、Git 操作等破坏性或有潜在影响的操作：

- 尽可能提供 `--dry-run` 或其他预览方式。
- 明确展示操作范围和预期效果。
- 必要时要求用户确认。
- 未经明确授权，不执行不可逆操作。
- 修改重要数据时考虑备份或恢复方案。

## 8. 文档

每个具有独立使用价值的工具在自身目录提供 `README.md`，按适用性包含：

- 用途与能力。
- 环境要求。
- 依赖安装。
- 运行方式。
- 参数与选项说明。
- 使用示例。
- 限制与安全注意事项。

trivial 的单文件工具可使用清晰的行内注释代替独立 README。

## 9. 参考实现

`src/git/set-git-config/` 体现了本规范的主要约定，可作为参照：

- 单文件、零第三方依赖，Node 标准库实现。
- 入口文件顶部的「默认配置」区与 CLI 覆盖逻辑。
- 必填值缺失时的用法输出与非零退出。
- 批量 Git 修改提供 `--dry-run` 预览。
- README 覆盖环境、参数、示例与注意事项。
